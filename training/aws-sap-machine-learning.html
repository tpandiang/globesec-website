Q1.A team wants to build a generative AI chat feature using foundation models from several providers through one API, without managing servers. Which service fits?
AAmazon SageMaker AI training jobs
BAmazon Comprehend
CAmazon Lex
DAmazon Bedrock
✓ Correct: D. Amazon Bedrock

How to think about it: Managed foundation models behind one API = Amazon Bedrock.

Why D is correct: Bedrock is serverless and offers models from Amazon and other providers through a unified API with pay-per-use pricing.

Why the others are wrong:
A) Amazon SageMaker AI training jobs — SageMaker is for building and training your own models, which is far more work than calling hosted FMs.
B) Amazon Comprehend — Comprehend is a fixed NLP service for sentiment and entities, not a generative model platform.
C) Amazon Lex — Lex builds intent-based chatbots; it is not a catalogue of foundation models.

AThe base model is retrained for every customer with your data
BYour tuned model is published in the Bedrock catalogue
CA private copy is tuned; your data never trains the base model
DThe model provider receives a copy of your data for review
✓ Correct: C. A private copy is tuned; your data never trains the base model

How to think about it: Fine-tune in Bedrock = your private copy; your data does not train the base model.

Why C is correct: Customizations stay in your account, and prompts and training data are not used to improve the providers' models.

Why the others are wrong:
A) The base model is retrained for every customer with your data — Your data is never folded into the shared base model.
B) Your tuned model is published in the Bedrock catalogue — Custom models are private to your account, not listed for others.
D) The model provider receives a copy of your data for review — Bedrock does not share your training data with the model provider.

Q3.A chatbot built on a foundation model gives generic answers because it does not know the company's internal documents. Which Bedrock feature adds that knowledge without retraining?
ABedrock Knowledge Bases (RAG)
BA higher temperature setting
CBedrock Guardrails
DContinued pre-training on the documents
✓ Correct: A. Bedrock Knowledge Bases (RAG)

How to think about it: Ground answers in your documents = Knowledge Bases (RAG).

Why A is correct: Knowledge Bases index your documents into a vector store and pass relevant passages to the model at query time.

Why the others are wrong:
B) A higher temperature setting — Temperature changes randomness, not what the model knows.
C) Bedrock Guardrails — Guardrails filter content and topics; they do not add knowledge.
D) Continued pre-training on the documents — This changes model weights, which is slower and costlier than retrieval for frequently changing documents.

AInside the foundation model's weights
BIn a DynamoDB table keyed by file name
CIn CloudWatch Logs for the application
DIn a vector store such as OpenSearch Serverless
✓ Correct: D. In a vector store such as OpenSearch Serverless

How to think about it: RAG lookup = vector store (for example OpenSearch Serverless).

Why D is correct: Embeddings are written to a vector database so semantically similar chunks can be found quickly.

Why the others are wrong:
A) Inside the foundation model's weights — RAG keeps the model unchanged and stores knowledge outside it.
B) In a DynamoDB table keyed by file name — A key-value lookup by name cannot do semantic similarity search.
C) In CloudWatch Logs for the application — Logs record activity; they are not a retrieval index.
