EBSFundamental
Q1.An EBS volume lives in us-east-1a and must be attached to an instance in us-east-1b. What is the standard way to move it?
ADetach it and attach it directly to the instance in us-east-1b
BEnable Multi-Attach so the us-east-1b instance can mount it
CChange the volume's Availability Zone with ModifyVolume
DSnapshot the volume and create a new volume from it in us-east-1b
✓ Correct: D. Snapshot the volume and create a new volume from it in us-east-1b

How to think about it: EBS is locked to one AZ: to move it, snapshot then restore in the other AZ.

Why D is correct: Snapshots are regional, so a volume restored from one can be created in any AZ of the Region.

Why the others are wrong:
A) Detach it and attach it directly to the instance in us-east-1b — A volume can only attach to instances in its own AZ, so a direct cross-AZ attach fails.
B) Enable Multi-Attach so the us-east-1b instance can mount it — Multi-Attach shares a volume among instances in the same AZ only.
C) Change the volume's Availability Zone with ModifyVolume — ModifyVolume changes size, type and performance, not the AZ.

Q2.Which EBS volume types can be used as a boot volume for an EC2 instance?
Ast1 and sc1 HDD volumes only
BOnly io2 Block Express volumes
Cgp2/gp3 and io1/io2 SSD volumes
DAny EBS type, including st1 and sc1
✓ Correct: C. gp2/gp3 and io1/io2 SSD volumes

How to think about it: Boot = SSD only: gp2/gp3 and io1/io2. The HDD types st1/sc1 cannot boot.

Why C is correct: The general purpose and provisioned IOPS SSD families can all serve as root volumes.

Why the others are wrong:
A) st1 and sc1 HDD volumes only — Throughput optimized and cold HDD volumes are data volumes and cannot be boot volumes.
B) Only io2 Block Express volumes — io2 can boot, but so can gp2, gp3 and io1.
D) Any EBS type, including st1 and sc1 — The HDD types are excluded from boot use, so not every type qualifies.

Q3.A log-processing cluster reads large files sequentially and needs high throughput at low cost per GB. Which EBS type fits best?
Ast1 Throughput Optimized HDD
Bgp3 General Purpose SSD
Cio2 Block Express SSD
Dsc1 Cold HDD
✓ Correct: A. st1 Throughput Optimized HDD

How to think about it: Big sequential reads, frequently accessed, cheap = st1. Rarely accessed and cheapest = sc1.

Why A is correct: st1 is a low-cost HDD built for frequently accessed, throughput-heavy sequential work such as logs and big data.

Why the others are wrong:
B) gp3 General Purpose SSD — gp3 is a balanced SSD; an HDD type is cheaper per GB for large sequential scans.
C) io2 Block Express SSD — io2 delivers very high IOPS for databases, but its cost per GB is far higher than needed here.
D) sc1 Cold HDD — sc1 is the cheapest HDD but is aimed at infrequently accessed data, so throughput is lower.

Q4.A database needs sustained, very high IOPS with sub-millisecond latency and the highest EBS durability. Which volume type is designed for this?
Agp2 General Purpose SSD
Bst1 Throughput Optimized HDD
CEC2 instance store NVMe
Dio2 Block Express
✓ Correct: D. io2 Block Express

How to think about it: Mission-critical, highest IOPS = io2 Block Express.

Why D is correct: io2 Block Express is the top-performance provisioned IOPS SSD, aimed at mission-critical, low-latency databases.

Why the others are wrong:
A) gp2 General Purpose SSD — gp2 ties IOPS to volume size and tops out far below provisioned IOPS volumes.
B) st1 Throughput Optimized HDD — st1 is tuned for sequential throughput, not random IOPS with low latency.
C) EC2 instance store NVMe — Instance store is fast but ephemeral, so it fails the durability requirement.

Q5.How do EBS snapshots store data after the first full snapshot?
AAs objects you can browse in your own S3 bucket
BAs a full copy of the volume every time
CAs a differential against the very first snapshot only
DIncrementally, saving only changed blocks
✓ Correct: D. Incrementally, saving only changed blocks

How to think about it: Snapshots are incremental: only changed blocks are saved after the first one.

Why D is correct: Each new snapshot stores only changed blocks, which keeps snapshot storage costs down.

Why the others are wrong:
A) As objects you can browse in your own S3 bucket — Snapshots are kept in AWS-managed S3 storage that you do not see as a bucket.
B) As a full copy of the volume every time — Full copies would be wasteful; EBS references unchanged blocks from earlier snapshots.
C) As a differential against the very first snapshot only — EBS tracks changes since the previous snapshot, not a growing differential from the first.

Q6.Volumes restored from snapshots show high first-read latency until every block is read. Which feature removes this warm-up delay?
ARecycle Bin for EBS snapshots
BFast Snapshot Restore on the snapshot
CEBS-optimized instances
DEBS Multi-Attach on the restored volume
✓ Correct: B. Fast Snapshot Restore on the snapshot

How to think about it: Restored volume slow on first read = enable Fast Snapshot Restore (FSR) (or read every block with fio/dd).

Why B is correct: FSR makes restored volumes fully initialized at creation, so they deliver full performance immediately.

Why the others are wrong:
A) Recycle Bin for EBS snapshots — Recycle Bin protects deleted snapshots from loss; it does not speed up restores.
C) EBS-optimized instances — EBS optimization gives dedicated bandwidth to EBS but does not pre-load snapshot blocks.
D) EBS Multi-Attach on the restored volume — Multi-Attach shares one volume among instances and has nothing to do with initialization.

Q9.Security requires every new EBS volume and snapshot in an account to be encrypted. How is this enforced most simply?
AEnable it once in the account's home Region
BTurn on S3 default encryption for the snapshot bucket
CEnable encryption on the instance's AMI only
DEnable EBS encryption by default in each Region used
✓ Correct: D. Enable EBS encryption by default in each Region used

How to think about it: EBS encryption by default is an account setting, and it is enabled per Region.

Why D is correct: This account-level setting encrypts all new volumes and snapshots, but it must be turned on in every Region.

Why the others are wrong:
A) Enable it once in the account's home Region — The setting is regional, so enabling it in one Region leaves the others unencrypted.
B) Turn on S3 default encryption for the snapshot bucket — Snapshots are not stored in a bucket you control, so S3 settings do not apply.

Q10.A clustered Linux application needs several instances in one AZ to read and write the same block volume at the same time. What is required?
AAn io2 volume with Multi-Attach formatted with EXT4
BA gp3 volume with Multi-Attach formatted with XFS
CAn io2 volume with Multi-Attach and a cluster-aware file system
DAn st1 volume shared through a placement group
✓ Correct: C. An io2 volume with Multi-Attach and a cluster-aware file system

How to think about it: Shared block volume = io1/io2 Multi-Attach, same AZ, plus a cluster-aware file system.

Why C is correct: Multi-Attach lets instances in one AZ share an io1/io2 volume, and the file system must coordinate concurrent writes.

Why the others are wrong:
A) An io2 volume with Multi-Attach formatted with EXT4 — EXT4 assumes a single writer, so concurrent writes from several hosts would corrupt it.
B) A gp3 volume with Multi-Attach formatted with XFS — Multi-Attach is not offered on gp3, and XFS is not cluster-aware, so data would be corrupted.
D) An st1 volume shared through a placement group — Placement groups control instance placement and do not let volumes be shared.

Q11.An application needs a very fast scratch area for temporary buffers, and the data can be lost. What gives the highest IOPS at no extra storage charge?
AAn EFS file system in Max I/O mode
BAn io2 Block Express volume
CEC2 instance store volumes
DA gp3 volume with maximum provisioned IOPS
✓ Correct: C. EC2 instance store volumes

How to think about it: Scratch, cache, temp data, highest IOPS = instance store (lost on stop or terminate).

Why C is correct: Instance store is physically attached to the host, giving very high IOPS, and its cost is included in the instance price.

Why the others are wrong:
A) An EFS file system in Max I/O mode — EFS is network file storage with higher latency than local disks.
B) An io2 Block Express volume — io2 is durable network storage billed per GB and per IOPS, which is more than temporary data needs.
D) A gp3 volume with maximum provisioned IOPS — gp3 is network-attached and cannot match the IOPS of local NVMe disks.
EBSFundamental
Q12.What happens to data on an EC2 instance store volume when the instance is stopped?
AThe data is saved to an automatic EBS snapshot
BThe data is lost
CThe data is moved to S3 and restored on start
DThe data is kept until the instance is terminated
✓ Correct: B. The data is lost

How to think about it: Instance store survives a reboot, but is lost on stop, hibernate or terminate.

Why B is correct: Stopping moves the instance to new hardware, so the local disks and their data are released.

Why the others are wrong:
A) The data is saved to an automatic EBS snapshot — AWS takes no automatic backup of instance store; the user must handle backups.
C) The data is moved to S3 and restored on start — There is no automatic copy to S3 for instance store volumes.
D) The data is kept until the instance is terminated — Only a reboot keeps instance store data; a stop already wipes it.

Q13.Many Linux instances across three AZs must share the same POSIX file system with no capacity planning. Which service fits?
AAmazon FSx for Windows File Server
BAmazon EFS
CAmazon S3 mounted as a bucket
DAn EBS io2 volume with Multi-Attach
✓ Correct: B. Amazon EFS

How to think about it: Shared Linux file system across AZs, grows automatically = EFS (NFSv4.1).

Why B is correct: EFS is a managed NFS file system mounted by many instances in several AZs, and it grows and shrinks automatically.

Why the others are wrong:
A) Amazon FSx for Windows File Server — FSx for Windows is an SMB share for Windows workloads, not the natural fit for POSIX Linux clients.
C) Amazon S3 mounted as a bucket — S3 is object storage and is not a POSIX file system with locking.
D) An EBS io2 volume with Multi-Attach — Multi-Attach is limited to one AZ and needs a cluster-aware file system.
EFSFundamental
Q14.Which statement about Amazon EFS client support is correct?
AIt exposes iSCSI block devices to clients
BIt is POSIX-compliant and supports Linux clients, not Windows
CIt supports both NFS and SMB clients
DIt is reached only through an S3-compatible API
✓ Correct: B. It is POSIX-compliant and supports Linux clients, not Windows

How to think about it: EFS = NFS for Linux. Windows file shares = FSx for Windows.

Why B is correct: EFS uses the NFS protocol and is not supported on Windows instances.

Why the others are wrong:
A) It exposes iSCSI block devices to clients — iSCSI is a block protocol offered by FSx for ONTAP, not EFS.
C) It supports both NFS and SMB clients — EFS speaks NFS only; SMB is offered by FSx for Windows and FSx for ONTAP.
D) It is reached only through an S3-compatible API — EFS is mounted as a file system over NFS, not accessed as objects.

Q15.How is network access to an EFS mount target controlled?
ARoute tables in the client's subnet only
BA VPC gateway endpoint for EFS
CAn S3 bucket policy attached to the file system
DA security group on the mount target allowing NFS traffic
✓ Correct: D. A security group on the mount target allowing NFS traffic

How to think about it: EFS mount targets are ENIs, so access is controlled by security groups (allow NFS port 2049).

Why D is correct: Each mount target is an ENI in a subnet, and its security group decides which clients can connect.

Why the others are wrong:
A) Route tables in the client's subnet only — Routing alone does not filter which clients may reach the NFS port.
B) A VPC gateway endpoint for EFS — EFS does not use gateway endpoints; clients connect to mount targets in the VPC.
C) An S3 bucket policy attached to the file system — Bucket policies apply to S3; EFS uses its own file system policy for IAM rules.

APerformance mode
BLifecycle policy for moving files to IA
CThe file system policy
DThroughput mode
✓ Correct: A. Performance mode

How to think about it: Performance mode (General Purpose vs Max I/O) is set at creation. Throughput mode can be changed.

AElastic throughput
BMax I/O performance mode

DProvisioned throughput
✓ Correct: A. Elastic throughput
