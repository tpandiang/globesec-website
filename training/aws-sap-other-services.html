CI/CDFundamental
Q1.What best describes continuous integration (CI)?
AEvery release is deployed to production by hand once a quarter
BInfrastructure is defined in templates instead of the console
CServers are patched automatically during maintenance windows
DDevelopers merge code often and each push is built and tested automatically
✓ Correct: D. Developers merge code often and each push is built and tested automatically

How to think about it: CI = push often, every push is built and tested automatically.

Why D is correct: CI gives quick feedback on every change so bugs are found and fixed early.

Why the others are wrong:
A) Every release is deployed to production by hand once a quarter — Infrequent manual releases are what CI and CD are meant to replace.
B) Infrastructure is defined in templates instead of the console — That is infrastructure as code, a related but separate practice.
C) Servers are patched automatically during maintenance windows — Patch automation is operations work, not integration of code changes.

CEvery passing build is deployed automatically and reliably
DCode reviews are replaced by automated unit tests
✓ Correct: C. Every passing build is deployed automatically and reliably

How to think about it: CD = every passing build can be released reliably, often, automatically.

Why C is correct: Continuous delivery automates deployment so a team can ship many small releases a day.

Why the others are wrong:
A) Developers commit code to a shared repository several times a day — Frequent commits are the CI part, not what delivery adds.
B) Builds run on a single shared on-premises server — Where builds run is not what defines continuous delivery.
D) Code reviews are replaced by automated unit tests — Delivery does not remove reviews; it automates the release path.
