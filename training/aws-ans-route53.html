Records & ZonesFundamental
Q1.What is the difference between a public and a private hosted zone?
APublic zones hold A records; private zones hold only CNAMEs
BPrivate zones need a Resolver inbound endpoint before they work
CPublic serves the internet; private serves associated VPCs
DPublic zones are free to run; private zones cost extra per VPC
✓ Correct: C. Public serves the internet; private serves associated VPCs

How to think about it: Public zone = answers the internet. Private zone = answers only the VPCs it is associated with.

Why C is correct: A private hosted zone is resolved by the Route 53 Resolver only for queries from VPCs associated with it.

Why the others are wrong:
A) Public zones hold A records; private zones hold only CNAMEs — Both kinds of zone support the usual record types.
B) Private zones need a Resolver inbound endpoint before they work — Inbound endpoints are only for on-premises clients. VPCs resolve private zones directly.
D) Public zones are free to run; private zones cost extra per VPC — Both kinds of hosted zone are billed the same way, with a monthly fee plus query charges.

Q2.Which two VPC settings must be turned on for a private hosted zone to resolve inside a VPC?
AA custom DHCP options set and an internet gateway
BenableNetworkAddressUsageMetrics and DNS64
CenableDnsSupport and enableDnsHostnames
DRoute 53 query logging and a CloudWatch log group
✓ Correct: C. enableDnsSupport and enableDnsHostnames

How to think about it: Private hosted zone = enableDnsSupport + enableDnsHostnames both set to true.

Why C is correct: DNS support turns on the .2 Resolver, and DNS hostnames is also required for private hosted zone resolution.

Why the others are wrong:
A) A custom DHCP options set and an internet gateway — Private zones work with the AmazonProvidedDNS default, and they don't need internet access.
B) enableNetworkAddressUsageMetrics and DNS64 — These are unrelated VPC features for metrics and IPv6 translation.
D) Route 53 query logging and a CloudWatch log group — Logging is optional and has no effect on resolution.

Q3.Which record type maps a hostname to an IPv6 address?
AA record
BAAAA record
CPTR record
DCNAME record
✓ Correct: B. AAAA record

How to think about it: A = IPv4, AAAA = IPv6, CNAME = name to name, NS = delegation.

Why B is correct: An AAAA record holds a 128-bit IPv6 address for the name.

Why the others are wrong:
A) A record — An A record holds an IPv4 address.
C) PTR record — PTR records do reverse lookups, from an IP address to a name.
D) CNAME record — A CNAME maps one name to another name, not to an IPv6 address.

Q4.Which two records does Route 53 create automatically in every new hosted zone?
ACAA and DS for certificates and DNSSEC
BNS and SOA
CA and AAAA for the zone apex
DMX and TXT for mail validation
✓ Correct: B. NS and SOA

How to think about it: New hosted zone = NS + SOA created for you.

Why B is correct: The NS record lists the zone's four name servers, and the SOA holds the zone's authority settings.

Why the others are wrong:
A) CAA and DS for certificates and DNSSEC — CAA and DS records are created only if you choose to add them.
C) A and AAAA for the zone apex — Apex address records are yours to create; they are not automatic.
D) MX and TXT for mail validation — Mail records are optional and are never created automatically.

Q5.What does a record's TTL control?
AHow long a record lasts before Route 53 deletes it
BHow often Route 53 health-checks the record's endpoint
CHow many hops a DNS query may take before being dropped
DHow long resolvers and clients may cache the DNS answer
✓ Correct: D. How long resolvers and clients may cache the DNS answer

How to think about it: TTL = how long resolvers cache the answer. High = fewer queries; low = faster changes.

Why D is correct: A long TTL lowers query volume and cost, but changes take longer to reach clients.

Why the others are wrong:
A) How long a record lasts before Route 53 deletes it — Records stay until you delete them; the TTL is only a caching hint.
B) How often Route 53 health-checks the record's endpoint — Health check intervals are set on the health check, not with the TTL.
C) How many hops a DNS query may take before being dropped — That is closer to the IP header's TTL field, not the DNS record TTL.
Records & ZonesFundamental
Q6.A team wants to manage dev.example.com in its own hosted zone while example.com stays elsewhere. What links the two?
ANS records for dev.example.com in the parent zone
BAssociating both zones with the same VPC
CA CNAME for dev.example.com that points to the new zone
DAn alias record at the parent apex for the subdomain zone
✓ Correct: A. NS records for dev.example.com in the parent zone

How to think about it: Subdomain in its own zone = NS records for the subdomain in the parent zone (delegation).

Why A is correct: Delegation puts the subdomain zone's name servers into the parent zone, so resolvers follow the referral.

Why the others are wrong:
B) Associating both zones with the same VPC — VPC association applies only to private zones and does not delegate anything.
C) A CNAME for dev.example.com that points to the new zone — A CNAME points one name at another name. It cannot delegate a zone.
D) An alias record at the parent apex for the subdomain zone — Alias targets are AWS resources, not hosted zones.
Records & ZonesAdvanced
Q7.Both a public zone example.com and a private zone example.com are associated with a VPC. An instance asks for api.example.com, which exists only in the public zone. What happens?
AThe query is forwarded to the on-premises DNS servers
BNXDOMAIN, because the matching private zone is authoritative
CIt gets both answers, merged from the two zones
DIt gets the public answer, because Resolver falls back automatically
✓ Correct: B. NXDOMAIN, because the matching private zone is authoritative

How to think about it: If a private zone matches the name, the VPC uses only the private zone. A missing record means NXDOMAIN, with no fallback to public.

Why B is correct: The Resolver uses the most specific matching private zone and does not fall back to the public zone when a record is missing.

Why the others are wrong:
A) The query is forwarded to the on-premises DNS servers — That happens only if a forwarding rule matches. None was set up here.
C) It gets both answers, merged from the two zones — Route 53 never merges answers from different zones.
D) It gets the public answer, because Resolver falls back automatically — There is no fallback. Copy the record into the private zone, or use a different private zone name.
Records & ZonesAdvanced
Q8.A private hosted zone in Account A must be resolvable from a VPC in Account B. What is the process?
AAuthorize in A, then associate the VPC from B
BCopy the zone file into a new private zone in Account B
CPeer the two VPCs; peering shares DNS zones automatically
DShare the hosted zone with AWS RAM to Account B
✓ Correct: A. Authorize in A, then associate the VPC from B

How to think about it: Cross-account private zone = create-vpc-association-authorization in A, then associate-vpc-with-hosted-zone from B.

Why A is correct: The zone owner creates an authorization for the other account's VPC, and that account then completes the association with the CLI, SDK or API.

Why the others are wrong:
B) Copy the zone file into a new private zone in Account B — This would work, but it creates two copies to maintain instead of one association.
C) Peer the two VPCs; peering shares DNS zones automatically — Peering does not share private hosted zones.
D) Share the hosted zone with AWS RAM to Account B — RAM shares Resolver rules, not private hosted zones.
AliasFundamental
Q9.Why choose an alias record instead of a CNAME for example.com (the zone apex)?
ACNAME records cannot point to any name outside AWS at all
BAlias records encrypt the DNS response sent to the client
CAlias records support much longer TTLs than CNAME records
DCNAMEs are not allowed at the zone apex, but alias records are
✓ Correct: D. CNAMEs are not allowed at the zone apex, but alias records are

How to think about it: Zone apex to an AWS resource = alias. CNAME is not allowed at the apex.

Why D is correct: DNS rules forbid a CNAME at the apex next to the SOA and NS records. An alias returns A or AAAA answers, so it can live there.

Why the others are wrong:
A) CNAME records cannot point to any name outside AWS at all — A CNAME can point at any hostname, inside or outside AWS.
B) Alias records encrypt the DNS response sent to the client — Neither record type encrypts responses.
C) Alias records support much longer TTLs than CNAME records — For an alias you cannot set a TTL; it uses the target's TTL.
AliasFundamental
Q10.Which target can an alias record not point to?
AAn EC2 instance's public DNS name
BAn Application Load Balancer
CAn S3 bucket configured as a static website
DA CloudFront distribution
✓ Correct: A. An EC2 instance's public DNS name

How to think about it: Alias targets = AWS resources (ELB, CloudFront, S3 website, API GW, VPC endpoint, GA, same-zone record). Not an EC2 DNS name.

Why A is correct: EC2 DNS names are not valid alias targets. Use an A record with the IP, or a CNAME.

Why the others are wrong:
B) An Application Load Balancer — ELB load balancers are standard alias targets.
C) An S3 bucket configured as a static website — S3 website endpoints are alias targets when the bucket name matches the record name.
D) A CloudFront distribution — CloudFront distributions are standard alias targets.

Q11.How are DNS queries to an alias record that points to an AWS resource such as an ALB billed?
AThey are billed at twice the standard query rate
BThey are free only when the TTL is set over one day
CThey are free of any Route 53 query charge
DThey are billed to the account that owns the target
✓ Correct: C. They are free of any Route 53 query charge

How to think about it: Alias to an AWS resource = no query charge.

Why C is correct: Queries to alias records that point at AWS resources have no charge, unlike CNAME queries.

Why the others are wrong:
A) They are billed at twice the standard query rate — There is no premium; such alias queries are free.
B) They are free only when the TTL is set over one day — You cannot set a TTL on an alias, and the free billing does not depend on TTL.
D) They are billed to the account that owns the target — The record is free to query; no other account is billed.

Q12.Which record type should point db.example.com at an RDS endpoint name?
AAn A record with the RDS instance's current IP address
BA CNAME record pointing to the RDS endpoint hostname
CAn alias record pointing directly to the RDS instance
DAn NS record that delegates db.example.com to RDS
✓ Correct: B. A CNAME record pointing to the RDS endpoint hostname

How to think about it: RDS endpoint = CNAME (RDS is not an alias target).

Why B is correct: RDS endpoints are DNS names whose IPs can change at failover, and alias does not support RDS.

Why the others are wrong:
A) An A record with the RDS instance's current IP address — The IP changes during failover or maintenance, so the record would go stale.
C) An alias record pointing directly to the RDS instance — RDS is not among the supported alias targets.
D) An NS record that delegates db.example.com to RDS — RDS does not host DNS zones, so there is nothing to delegate to.

Q13.Clients in a VPC should reach an interface endpoint for a partner service as partner.internal.corp. What record should you create in your private zone?
AA PTR record that maps the endpoint IP to the name
BAn A record with one of the endpoint ENI IP addresses
CAn alias to the interface VPC endpoint DNS name
DAn NS record delegating to the partner's hosted zone
✓ Correct: C. An alias to the interface VPC endpoint DNS name

How to think about it: Friendly name for an interface endpoint = alias to the VPC endpoint DNS name.

Why C is correct: Interface endpoints are supported alias targets, and the alias follows the endpoint's ENI IPs.

Why the others are wrong:
A) A PTR record that maps the endpoint IP to the name — PTR records do reverse lookups, not forward lookups.
B) An A record with one of the endpoint ENI IP addresses — This works but hard-codes one AZ's IP and loses the endpoint's multi-AZ behaviour.
D) An NS record delegating to the partner's hosted zone — The partner's zone is not reachable from your VPC, and delegation is the wrong tool here.
Routing PoliciesFundamental
Q14.Which routing policy splits traffic by percentage, for example 90% to v1 and 10% to v2?
AWeighted
BFailover
CLatency-based
DMultivalue answer
✓ Correct: A. Weighted

How to think about it: Percentage split, canary or blue/green = weighted.

Why A is correct: Each record gets a weight, and Route 53 answers in proportion to weight over the total.

Why the others are wrong:
B) Failover — Failover is active-passive: the secondary is used only when the primary is unhealthy.
C) Latency-based — Latency routing picks the Region with the lowest latency, not a percentage.
D) Multivalue answer — Multivalue returns up to eight healthy records at random, with no weights.

Q15.Which routing policy sends users to the AWS Region that gives them the lowest network latency?
ASimple routing
BGeolocation
CIP-based routing
DLatency-based
✓ Correct: D. Latency-based

How to think about it: Fastest Region for the user = latency-based routing.

Why D is correct: Route 53 uses measured latency between user networks and AWS Regions to pick the record.

Why the others are wrong:
A) Simple routing — Simple returns a fixed answer with no regional awareness.
B) Geolocation — Geolocation routes by the user's country or continent, not by measured latency.
C) IP-based routing — IP-based routing maps client CIDR blocks you list, not measured latency.

Q16.Which routing policy answers by the user's continent, country or US state, for example for content licensing?
AGeolocation
BLatency-based
CGeoproximity
DWeighted
✓ Correct: A. Geolocation

How to think about it: Where the user is (country, continent, state) = geolocation. Add a default record for unmatched users.

Why A is correct: Geolocation matches the user's location. A default record catches locations that have no match.

Why the others are wrong:
B) Latency-based — Latency follows network performance, which may cross country borders.
C) Geoproximity — Geoproximity uses the distance to resources plus a bias, not fixed country rules.
D) Weighted — Weighted routing ignores where the user is.

Q17.Which routing policy lets you widen or shrink a Region's share of traffic with a bias value?
AGeoproximity
BLatency-based
CWeighted
DGeolocation
✓ Correct: A. Geoproximity

How to think about it: Bias on a geographic area = geoproximity (now in plain records or Traffic Flow).

Why A is correct: Geoproximity routes to the nearest resource, and a bias grows or shrinks each resource's area. It can now be set up without Traffic Flow.

Why the others are wrong:
B) Latency-based — Latency routing has no bias setting.
C) Weighted — Weights split traffic, but they don't use geography.
D) Geolocation — Geolocation uses fixed location matches with no bias setting.

Q18.What does multivalue answer routing return?
AEvery record in the set, healthy or not, in a fixed order
BOnly the single record with the highest weight
CThe record from the Region closest to the user
DUp to eight healthy records, picked at random
✓ Correct: D. Up to eight healthy records, picked at random

How to think about it: Multivalue = up to 8 healthy records per answer, with client-side spreading. It is not a load balancer.

Why D is correct: With health checks attached, unhealthy values are left out, so clients spread load over the healthy ones.

Why the others are wrong:
A) Every record in the set, healthy or not, in a fixed order — That is closer to simple routing with several values. It ignores health.
B) Only the single record with the highest weight — Weights belong to weighted routing.
C) The record from the Region closest to the user — That is geoproximity or latency routing.

Q19.Which routing policy uses CIDR blocks you supply, for example to send one ISP's users to a set endpoint?
AGeolocation routing with a country list
BWeighted routing with a weight for each ISP
CSimple routing with several IP values
DIP-based routing with CIDR collections
✓ Correct: D. IP-based routing with CIDR collections

How to think about it: Route by client CIDR = IP-based routing (CIDR collections).

Why D is correct: You group client CIDRs into collections and map each one to a record, which is useful for ISP-specific routing.

Why the others are wrong:
A) Geolocation routing with a country list — Countries are larger than ISP ranges and are not chosen by CIDR.
B) Weighted routing with a weight for each ISP — Weights don't know where a query comes from.
C) Simple routing with several IP values — Simple routing returns the same values to everyone.

Q20.What does a simple routing record with three IP values return, and can it use health checks?
AThe IP closest to the user, with health checks required
BOne IP chosen by weight, with optional health checks
COnly the first IP, with the others kept as failover backups
DAll three IPs in random order, and it cannot be health-checked
✓ Correct: D. All three IPs in random order, and it cannot be health-checked

How to think about it: Simple = all values returned, client picks one, no health checks.

Why D is correct: Simple routing returns every value and the client chooses one. Use multivalue if unhealthy IPs must be left out.

Why the others are wrong:
A) The IP closest to the user, with health checks required — Proximity-based answers need latency or geoproximity routing.

AIncrease the TTL so the user's resolver caches more
BAdd a geolocation record with the Default location
CAttach a health check to the European record
DSwitch the records to latency-based routing
✓ Correct: B. Add a geolocation record with the Default location

A) Increase the TTL so the user's resolver caches more — Caching an empty answer longer does not help.

Q22.You want a primary site with automatic DNS switchover to a static S3 maintenance page if the primary fails. What setup fits?
AWeighted routing at 100 and 0 with no health checks
BMultivalue routing that returns both the site and the S3 bucket
CLatency routing between the site and the S3 Region
DFailover routing: health-checked primary, secondary alias to S3
✓ Correct: D. Failover routing: health-checked primary, secondary alias to S3

How to think about it: Active-passive = failover routing: primary with a health check, secondary alias to S3.

Why D is correct: When the primary health check fails, Route 53 answers with the secondary record, which points at the S3 site.

Why the others are wrong:
A) Weighted routing at 100 and 0 with no health checks — Without health checks Route 53 cannot tell that the primary failed.
B) Multivalue routing that returns both the site and the S3 bucket — Clients would get the maintenance page some of the time even while the primary is healthy.
C) Latency routing between the site and the S3 Region — Latency decides by speed, not by health, so it would not switch.

ATraffic Flow with a traffic policy and policy record

CRoute 53 Application Recovery Controller cells
DA CloudFormation template with a single simple record

Health ChecksFundamental
Q24.Which three kinds of Route 53 health checks exist?
AInstance, volume, and ENI status
BPing, traceroute, and SNMP based
CEndpoint, calculated, CloudWatch alarm
DPublic, private, and hybrid zone checks
✓ Correct: C. Endpoint, calculated, CloudWatch alarm

How to think about it: Health checks = endpoint, calculated (combines children), CloudWatch alarm.

Why C is correct: You can monitor an endpoint directly, combine child checks with AND/OR logic, or follow a CloudWatch alarm.

Why the others are wrong:
A) Instance, volume, and ENI status — These are EC2 status ideas, not Route 53 health check types.
B) Ping, traceroute, and SNMP based — Route 53 health checks use HTTP, HTTPS or TCP, not these tools.
D) Public, private, and hybrid zone checks — Health checks are not grouped by zone type.
Health ChecksFundamental
Q25.Route 53 health checkers run outside your VPC. How do you health-check a resource that has only a private IP?
APoint an endpoint health check directly at the private IP
BPut the health checker inside the VPC with an interface endpoint
CCreate a CloudWatch alarm on a metric and health-check the alarm
DUse a calculated check with no child health checks
✓ Correct: C. Create a CloudWatch alarm on a metric and health-check the alarm

How to think about it: Private resource = CloudWatch metric + alarm, then a health check on the alarm.

Why C is correct: The checkers cannot reach private IPs, so you watch a metric and let the health check follow the alarm state.

Why the others are wrong:
A) Point an endpoint health check directly at the private IP — The checkers run on the internet and cannot reach private addresses.
B) Put the health checker inside the VPC with an interface endpoint — There is no in-VPC endpoint for Route 53 health checkers.
D) Use a calculated check with no child health checks — A calculated check needs child checks, and those would still need to reach the resource.
Health ChecksFundamental
Q26.Which HTTP status codes does a Route 53 HTTP or HTTPS endpoint health check count as healthy?
AAny response received within ten seconds
BAny 2xx or 3xx status code
COnly exactly 200 OK
DAny status except 5xx server errors
✓ Correct: B. Any 2xx or 3xx status code

How to think about it: Healthy = 2xx or 3xx (optionally plus a string match in the first 5,120 bytes).

Why B is correct: Responses from 200 to 399 pass. You can also require a string to appear in the first part of the body.

Why the others are wrong:
A) Any response received within ten seconds — The status code matters, not only that a reply arrived.
C) Only exactly 200 OK — Redirects (3xx) also count as healthy.
D) Any status except 5xx server errors — 4xx client errors count as failures.

Q27.A web tier is healthy only if at least 2 of its 3 regional endpoints pass. How do you express this in Route 53?
AA CloudWatch alarm on HealthCheckPercentageHealthy only
BA multivalue record that needs two healthy answers
CA calculated check with child checks and threshold 2
DThree endpoint checks with the failure threshold set to 2
✓ Correct: C. A calculated check with child checks and threshold 2

Domains & DNSSECFundamental
Q29.What does DNSSEC protect against?
AEavesdropping, by encrypting DNS queries in transit
BDDoS floods aimed at the hosted zone's name servers
CUnauthorized IAM users changing records in the zone
DForged or tampered DNS answers, such as cache poisoning
✓ Correct: D. Forged or tampered DNS answers, such as cache poisoning

How to think about it: DNSSEC = signed records = stops spoofing and cache poisoning. It does not encrypt.

Why D is correct: DNSSEC signs records so resolvers can check where they came from and that they are intact.

Why the others are wrong:
A) Eavesdropping, by encrypting DNS queries in transit — DNSSEC gives authenticity, not secrecy. Encryption comes from DoH or DoT.
B) DDoS floods aimed at the hosted zone's name servers — Shield and Route 53's anycast design handle volume attacks.
C) Unauthorized IAM users changing records in the zone — Who can change records is controlled by IAM policies, not by DNSSEC.
Domains & DNSSECFundamental
Q30.When you enable DNSSEC signing in Route 53, which key do you manage, and where?
AThe ZSK, from a symmetric KMS key in the zone's Region
BThe KSK, via an asymmetric KMS key in us-east-1
CNo key at all, because Route 53 fully manages both
DBoth keys, uploaded as PEM files to the hosted zone
✓ Correct: B. The KSK, via an asymmetric KMS key in us-east-1

How to think about it: KSK = yours, backed by an asymmetric customer-managed KMS key in us-east-1. ZSK = AWS-managed.

Why B is correct: Route 53 builds the key-signing key from your KMS key (ECC_NIST_P256) in N. Virginia, and manages the zone-signing key itself.

Why the others are wrong:
A) The ZSK, from a symmetric KMS key in the zone's Region — AWS manages the ZSK, and the KSK needs an asymmetric key in us-east-1.
C) No key at all, because Route 53 fully manages both — You create or select the KMS key behind the KSK.
D) Both keys, uploaded as PEM files to the hosted zone — You don't upload keys. The KSK comes from KMS.

Q31.Which DNSSEC feature does Route 53 support only for public hosted zones?
AAlias records that point at AWS resources
BHealth checks on records in the zone
CWeighted routing between multiple records
DDNSSEC signing of the zone's records
✓ Correct: D. DNSSEC signing of the zone's records

How to think about it: DNSSEC signing = public hosted zones only. Validation is done by the Resolver.

Why D is correct: Route 53 signs public hosted zones. Private zones cannot be signed.

Why the others are wrong:
A) Alias records that point at AWS resources — Alias records work in both zone types.
B) Health checks on records in the zone — Health checks work with both public and private records, and they are not part of DNSSEC.
C) Weighted routing between multiple records — Weighted routing works in both zone types.

Q33.What IP address does a VPC's Route 53 Resolver (AmazonProvidedDNS) use?
AAny IP you assign when creating a DHCP options set
BThe VPC CIDR base plus two, or 169.254.169.253
CThe first usable IP in every subnet, the .1 address
D8.8.8.8, forwarded through the internet gateway

Q40.A forwarding rule sends all of corp.local on-premises, but aws.corp.local is a private hosted zone in the VPC and should resolve locally. What fixes this?
ADelete the forwarding rule and use the private zone for everything
BAdd a System rule for aws.corp.local so the Resolver answers it
CLower the TTL of the private zone records to 0 seconds
DCreate a second outbound endpoint just for aws.corp.local
✓ Correct: B. Add a System rule for aws.corp.local so the Resolver answers it

How to think about it: Carve a subdomain out of a forward rule = a System rule for the more specific name.

Why B is correct: The most specific rule wins, and a System rule tells the Resolver to resolve that name itself, including from private zones.

Why the others are wrong:
A) Delete the forwarding rule and use the private zone for everything — The on-premises corp.local names would then stop resolving.
C) Lower the TTL of the private zone records to 0 seconds — TTL has no effect on which rule handles the query.
D) Create a second outbound endpoint just for aws.corp.local — Endpoints don't choose domains; rules do. This would still forward on-premises.
