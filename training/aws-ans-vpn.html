BGP & RoutingFundamental
Q1.What is the main difference between static and dynamic routing on a VPN connection?
ADynamic routing learns prefixes automatically through BGP
BStatic routing fails over between tunnels faster than BGP does
CStatic routing encrypts traffic while dynamic routing does not
DDynamic routing is only available on Direct Connect, never on VPN
✓ Correct: A. Dynamic routing learns prefixes automatically through BGP

How to think about it: Dynamic = routes are learned automatically (BGP); static = you type every prefix yourself.

Why A is correct: With BGP, each side advertises its networks, so new on-premises ranges appear on the AWS side without manual edits.

Why the others are wrong:
B) Static routing fails over between tunnels faster than BGP does — Static routing has no protocol to detect path changes; BGP gives faster, automatic failover.
C) Static routing encrypts traffic while dynamic routing does not — Both routing types run inside the same IPsec tunnels; encryption is identical.
D) Dynamic routing is only available on Direct Connect, never on VPN — Site-to-Site VPN supports BGP; it is the recommended option.

Q2.Which private ASN range can you assign to a Virtual Private Gateway (2-byte)?
A65535 to 131071
B64512 to 65534
C1 to 64495
D7224 to 7300
✓ Correct: B. 64512 to 65534

How to think about it: Private 2-byte ASN = 64512–65534; AWS default for a VGW is 64512.

Why B is correct: This is the private 2-byte ASN range; AWS uses 64512 by default if you choose nothing.

Why the others are wrong:
A) 65535 to 131071 — 65535 is reserved and 65536+ are 4-byte numbers, not the 2-byte private range.
C) 1 to 64495 — This is the public ASN range assigned by registries, not for private use.
D) 7224 to 7300 — 7224 is the Amazon public ASN, used in BGP communities; it is not a private range.

Q3.Which BGP attribute is used inside your own AS to choose the outbound path, with the higher value preferred?
ALOCAL_PREF
BMED (Multi-Exit Discriminator)
CCisco Weight
DAS_PATH length
✓ Correct: A. LOCAL_PREF

How to think about it: Leaving my AS, inside my AS = LOCAL_PREF (highest wins).

Why A is correct: Local preference is shared between your internal routers to pick the exit path; the highest value wins.

Why the others are wrong:
B) MED (Multi-Exit Discriminator) — MED is sent to a neighbouring AS to influence how it enters yours; lowest wins.
C) Cisco Weight — Weight is a Cisco-only setting local to a single router and is not shared with other routers.
D) AS_PATH length — AS_PATH length is compared after LOCAL_PREF and is visible across autonomous systems.

Q4.When two paths reach the same prefix between the same pair of autonomous systems, which MED value is preferred?
AMED is ignored when both paths come from the same AS
BThe highest MED value
CThe MED value closest to 100
DThe lowest MED value
✓ Correct: D. The lowest MED value

How to think about it: MED: lower is better.

Why D is correct: MED (Multi-Exit Discriminator) is a hint to the neighbour AS; a lower value means a more preferred entry point.

Why the others are wrong:
A) MED is ignored when both paths come from the same AS — Comparing paths from the same neighbouring AS is exactly when MED is used.
B) The highest MED value — Higher wins for LOCAL_PREF and Weight, not for MED.
C) The MED value closest to 100 — There is no target value; BGP simply compares and picks the lowest.

Q5.Your on-premises router advertises 10.0.0.0/16 on two BGP sessions. You want AWS to prefer the first path and keep the second as backup. Which technique works from the customer side without changing prefix length?
AAdvertise the same prefix with a different MD5 password
BPrepend your ASN several times on the backup path
CLower the BGP hold timer on the backup session
DSet a higher LOCAL_PREF on the backup advertisement
✓ Correct: B. Prepend your ASN several times on the backup path

How to think about it: Make the backup look longer = AS_PATH prepending.

Why B is correct: A longer AS_PATH makes the backup less attractive, so AWS picks the shorter path.

Why the others are wrong:
A) Advertise the same prefix with a different MD5 password — The MD5 key only authenticates the session; it has no role in path selection.
C) Lower the BGP hold timer on the backup session — Timers only affect how fast a failure is detected, not which path is chosen.
D) Set a higher LOCAL_PREF on the backup advertisement — LOCAL_PREF is not passed to an external peer, so AWS would never see it.

Q7.What is a Virtual Private Gateway (VGW)?
AA physical router you install in your own data center
BThe AWS-side VPN and DX endpoint attached to one VPC
CA regional hub that connects thousands of VPCs together
DA NAT device that gives private subnets internet access
✓ Correct: B. The AWS-side VPN and DX endpoint attached to one VPC

How to think about it: VGW = the AWS-side VPN/DX endpoint for one VPC.

Why B is correct: A VGW terminates VPN tunnels and private VIFs; one VGW is attached to one VPC at a time.

Why the others are wrong:
A) A physical router you install in your own data center — That is the customer gateway device, on your side of the tunnel.
C) A regional hub that connects thousands of VPCs together — That describes a Transit Gateway, not a VGW.
D) A NAT device that gives private subnets internet access — That is a NAT gateway; a VGW does not provide internet access.

Q8.In AWS, what does the customer gateway (CGW) resource represent?
AA managed VPN appliance that AWS ships to your site
BA route table that AWS attaches to each VPN connection
CThe backup VPN tunnel that AWS adds for redundancy
DA record of your device's public IP and BGP ASN
✓ Correct: D. A record of your device's public IP and BGP ASN

How to think about it: CGW resource = AWS's record of your device (public IP + ASN).

Why D is correct: The CGW resource tells AWS where your side of the tunnel is and how it does BGP.

Why the others are wrong:
A) A managed VPN appliance that AWS ships to your site — AWS ships no hardware for VPN; the CGW is just a configuration record.
B) A route table that AWS attaches to each VPN connection — Routing lives in VPC or TGW route tables; the CGW only describes your device.
C) The backup VPN tunnel that AWS adds for redundancy — Each VPN connection has two tunnels; the CGW is not one of them.

Q13.A VGW-based VPN uses BGP. On-premises adds a new subnet, but EC2 instances can't reach it. The CGW shows the prefix being advertised. What is the most likely missing step?
AThe VPN must be changed from IPsec to GRE tunnels
BThe VGW ASN must be changed to a public ASN
CRoute propagation is off on the subnet's route table
DA second customer gateway must be created for the new subnet
✓ Correct: C. Route propagation is off on the subnet's route table

How to think about it: BGP routes reach a VPC route table only with route propagation enabled.

Why C is correct: Without propagation, routes learned from the VGW are never added to the VPC route table.

Why the others are wrong:
A) The VPN must be changed from IPsec to GRE tunnels — Protocol has nothing to do with route learning; GRE is not supported anyway.
B) The VGW ASN must be changed to a public ASN — A private ASN works fine for BGP over VPN.

CLower the DPD timeout value on tunnel 2 only

Q16.What is Dead Peer Detection (DPD) used for on a Site-to-Site VPN?
ADetecting that the IPsec peer is no longer responding
BReplacing a failed tunnel endpoint with a new public IP
CBlocking traffic from IP addresses known to be malicious
DDiscovering the best MTU along the tunnel path
✓ Correct: A. Detecting that the IPsec peer is no longer responding

How to think about it: DPD = R-U-THERE keepalives to detect a dead IPsec peer.

Why A is correct: AWS sends R-U-THERE messages and acts (clear or restart) if no reply arrives within the timeout.

Why the others are wrong:
B) Replacing a failed tunnel endpoint with a new public IP — Endpoint replacement is an AWS maintenance task, not part of DPD.
C) Blocking traffic from IP addresses known to be malicious — That is a firewall or WAF job, not DPD.
D) Discovering the best MTU along the tunnel path — AWS managed VPN does not support Path MTU Discovery; DPD is unrelated.

Q17.Which DPD timeout action makes AWS restart IKE negotiation instead of simply ending the session?
AClear (default)
BDrop and log
CNone
DRestart
✓ Correct: D. Restart

How to think about it: DPD actions: Clear (default) ends it, Restart renegotiates, None does nothing.

Why D is correct: Restart makes AWS start IKE phase 1 again, so the tunnel comes back without the CGW initiating.

Why the others are wrong:
A) Clear (default) — Clear is the default: it ends the IKE session, stops the tunnel and clears its routes.
B) Drop and log — Drop is not one of the DPD timeout actions.
C) None — None takes no action when the peer stops responding.

Q18.A VPN tunnel goes down repeatedly at night when no traffic flows, and the CGW doesn't support DPD well. What is the simplest fix?
AMove the VPN termination from the VGW to a NAT gateway
BIncrease the VPC CIDR to a /16 to add capacity
CKeep traffic, such as pings, flowing in the tunnel
DSwitch the VPN connection from BGP to static routing
✓ Correct: C. Keep traffic, such as pings, flowing in the tunnel

How to think about it: Idle tunnel dropping = keep it busy (keepalive ping) or let AWS initiate the tunnel.

Why C is correct: Constant traffic stops idle timeouts; you can also set the tunnel startup action so AWS starts IKE.

Why the others are wrong:
A) Move the VPN termination from the VGW to a NAT gateway — A NAT gateway cannot terminate VPN tunnels.
B) Increase the VPC CIDR to a /16 to add capacity — The VPC address range has nothing to do with tunnel idle behaviour.
D) Switch the VPN connection from BGP to static routing — Routing type doesn't stop idle timeouts; BGP keepalives actually help.

B) Attach an Elastic Fabric Adapter — EFA is for HPC traffic between instances, not routing.
C) Enable termination protection — This only prevents accidental deletion.
