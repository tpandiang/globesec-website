Layered DefenseFundamental
Q1.Which statement correctly compares security groups and network ACLs?
ASGs are stateless at the subnet; NACLs are stateful at the ENI
BBoth are stateful, and both support explicit deny rules for CIDRs
CBoth are stateless and evaluated only at the internet gateway
DSGs are stateful at the ENI; NACLs are stateless at the subnet
✓ Correct: D. SGs are stateful at the ENI; NACLs are stateless at the subnet

How to think about it: SG = stateful, ENI-level, allow-only; NACL = stateless, subnet-level, allow + deny.

Why D is correct: Return traffic is automatically allowed by an SG, while a NACL needs explicit rules in both directions and applies to the whole subnet.

Why the others are wrong:
A) SGs are stateless at the subnet; NACLs are stateful at the ENI — This reverses both properties: SGs are stateful and attach to ENIs, NACLs are stateless and attach to subnets.
B) Both are stateful, and both support explicit deny rules for CIDRs — Only NACLs support deny rules, and NACLs are stateless.
C) Both are stateless and evaluated only at the internet gateway — Neither is tied to the internet gateway; SGs apply at the ENI and NACLs at the subnet boundary.

Q2.You must block one specific malicious source IP from reaching instances in a subnet. Which control can do this directly?
AA security group deny rule on the instance
BAn IAM policy with a aws:SourceIp condition
CA VPC route table blackhole route for the source IP
DA network ACL deny rule on the subnet
✓ Correct: D. A network ACL deny rule on the subnet

How to think about it: Need to deny an IP at the VPC layer = NACL (SGs have no deny).

Why D is correct: NACLs support explicit deny rules by CIDR, so a /32 deny blocks that address for the whole subnet.

Why the others are wrong:
A) A security group deny rule on the instance — Security groups only have allow rules; you cannot write a deny in an SG.
B) An IAM policy with a aws:SourceIp condition — IAM conditions control API calls to AWS services, not packets reaching an EC2 instance.
C) A VPC route table blackhole route for the source IP — Route tables decide where traffic goes; they do not filter inbound sources reaching the subnet.

Q3.Users reach an ALB through CloudFront. Security wants to block a single abusive client IP. Why won't a NACL on the ALB subnets work, and what should you use?
ANACLs only filter IPv6 here; add a route table drop for the client IP
BTLS hides the client IP; use Shield Standard to block that client
CNACLs can't apply to ALB subnets; use a security group deny rule
DThe ALB sees CloudFront IPs, not the client; use a WAF IP set rule
✓ Correct: D. The ALB sees CloudFront IPs, not the client; use a WAF IP set rule

How to think about it: Behind CloudFront the packet source is a CloudFront IP, so filter the real client with AWS WAF.

Why D is correct: CloudFront opens its own connections to the origin, so the client IP only exists in headers; WAF on CloudFront can match the real viewer IP.

Why the others are wrong:
A) NACLs only filter IPv6 here; add a route table drop for the client IP — NACLs handle IPv4 and IPv6, and route tables cannot drop traffic by source address.
B) TLS hides the client IP; use Shield Standard to block that client — TLS does not hide IP headers, and Shield Standard is automatic L3/L4 DDoS protection, not a per-IP block list.
C) NACLs can't apply to ALB subnets; use a security group deny rule — NACLs do work on ALB subnets, and security groups cannot deny; the real problem is the source IP being CloudFront's.

Q4.An origin ALB should accept traffic only from CloudFront. What is the simplest way to express that in the ALB security group?
AReference the CloudFront distribution ID as the SG source
BReference the AWS-managed CloudFront origin-facing prefix list
CAllow 0.0.0.0/0 and rely on CloudFront geo restriction
DAdd every CloudFront edge IP from ip-ranges.json as a /32 rule by hand
✓ Correct: B. Reference the AWS-managed CloudFront origin-facing prefix list

How to think about it: Allow only CloudFront to the origin = the com.amazonaws.global.cloudfront.origin-facing managed prefix list.

Why B is correct: AWS maintains this prefix list with CloudFront's origin-facing IP ranges, so the SG rule stays current without manual updates.

Why the others are wrong:
A) Reference the CloudFront distribution ID as the SG source — Security groups accept CIDRs, prefix lists or other SGs, not a CloudFront distribution ID.
C) Allow 0.0.0.0/0 and rely on CloudFront geo restriction — Opening the SG to everyone lets clients bypass CloudFront and hit the ALB directly.
D) Add every CloudFront edge IP from ip-ranges.json as a /32 rule by hand — This is brittle and quickly exceeds SG rule limits; the managed prefix list does it for you.

Q5.At which OSI layer does AWS WAF inspect traffic?
ALayer 4, inspecting TCP and UDP flows only
BLayer 3, inspecting IP packets of any protocol
CLayer 7, inspecting HTTP and HTTPS requests
DLayer 2, inspecting Ethernet frames in the VPC
✓ Correct: C. Layer 7, inspecting HTTP and HTTPS requests

How to think about it: WAF = Layer 7 (HTTP/HTTPS requests).

Why C is correct: WAF evaluates request components such as headers, URI, query string and body.

Why the others are wrong:
A) Layer 4, inspecting TCP and UDP flows only — WAF does not inspect raw TCP/UDP flows; it understands HTTP requests.
B) Layer 3, inspecting IP packets of any protocol — Packet-level filtering of any protocol is the job of NACLs or AWS Network Firewall.
D) Layer 2, inspecting Ethernet frames in the VPC — Nothing in AWS exposes customer filtering at the Ethernet frame layer.

Q7.When a request matches a WAF rule with a Block action, what does the client receive by default?
AAn HTTP 403 Forbidden response
BAn HTTP 302 redirect to a CAPTCHA page
CAn HTTP 503 Service Unavailable response
DA TCP reset with no HTTP response
✓ Correct: A. An HTTP 403 Forbidden response

How to think about it: WAF block = HTTP 403 Forbidden (a custom response is optional).

Why A is correct: WAF returns 403 by default for blocked requests; you can configure a custom response code and body.

Why the others are wrong:
B) An HTTP 302 redirect to a CAPTCHA page — CAPTCHA and Challenge are separate rule actions; the Block action returns 403.
C) An HTTP 503 Service Unavailable response — 503 indicates the backend is unavailable, which is not WAF's default block response.
D) A TCP reset with no HTTP response — WAF works at the HTTP layer and returns an HTTP response, not a bare TCP reset.

Q8.A login endpoint is being hammered by a single IP sending thousands of requests per minute. Which WAF rule type throttles this?
AA size constraint rule on the login request body
BA rate-based rule that blocks IPs above a threshold
CA SQL injection match rule on the login query string
DA geo match rule that blocks the IP's whole country
✓ Correct: B. A rate-based rule that blocks IPs above a threshold

How to think about it: Too many requests from one source = rate-based rule.

Why B is correct: Rate-based rules count requests per source over a time window and act when the threshold is exceeded.

Why the others are wrong:
A) A size constraint rule on the login request body — Size constraints check how big a request part is, not how often a client sends requests.
C) A SQL injection match rule on the login query string — SQLi rules detect malicious payloads, not high request volumes.
D) A geo match rule that blocks the IP's whole country — Geo blocking would block every user in that country, not just the one abusive client.

Q10.A team wants to see what a new WAF rule would block in production before enforcing it. What should they do?
ASet the rule action to Count and review the matched requests
BDeploy the rule with Block in a separate web ACL on the same ALB
CEnable Shield Advanced and ask the SRT to simulate traffic
DSet the default action of the web ACL to Block for one hour
✓ Correct: A. Set the rule action to Count and review the matched requests

How to think about it: Test a rule safely = set its action to Count and review metrics/logs.

Why A is correct: Count records matches in metrics and logs without blocking, so you can tune the rule before switching to Block.

Why the others are wrong:
B) Deploy the rule with Block in a separate web ACL on the same ALB — A resource can have only one web ACL associated, and Block would still affect users.
C) Enable Shield Advanced and ask the SRT to simulate traffic — The Shield Response Team helps during DDoS events; it is not a rule testing service.
D) Set the default action of the web ACL to Block for one hour — Blocking by default would deny all non-matching legitimate traffic.

Q11.What is a SYN flood attack?
AMany half-open TCP connections exhausting the server's state
BA flood of DNS queries that overwhelms the authoritative name server
CSpoofed UDP queries that make third-party servers reply to the victim
DMany slow HTTP connections held open by sending partial headers
✓ Correct: A. Many half-open TCP connections exhausting the server's state

How to think about it: SYN flood = lots of half-open TCP handshakes exhausting the server.

Why A is correct: The attacker sends SYNs and never completes the handshake, tying up server resources.

Why the others are wrong:
B) A flood of DNS queries that overwhelms the authoritative name server — That is a DNS flood, aimed at stopping name resolution.
C) Spoofed UDP queries that make third-party servers reply to the victim — That describes a UDP reflection/amplification attack.
D) Many slow HTTP connections held open by sending partial headers — That is a Slowloris application-layer attack.

Q16.A public web app on EC2 behind an ALB must survive large DDoS attacks at the lowest operational effort. Which architecture follows AWS best practice?
AGive every EC2 instance a public IP so load spreads across many addresses
BCloudFront + WAF in front of the ALB, ALB locked to CloudFront

DAdd NACL deny rules for each attacking IP as soon as it appears
✓ Correct: B. CloudFront + WAF in front of the ALB, ALB locked to CloudFront

Q19.How does a stateless rule group in Network Firewall behave?
AIt decrypts HTTPS sessions and inspects the HTTP request body
BIt tracks connection state and allows return traffic automatically
CIt filters traffic by domain name using the TLS SNI field
DEach packet is checked alone on 5-tuple fields, in priority order
✓ Correct: D. Each packet is checked alone on 5-tuple fields, in priority order

Q20.Which actions are available for a Network Firewall stateless rule?

BAllow, Block, Count, or CAPTCHA
CPass, Drop, or Forward to stateful
DAccept, Reject, or Log and continue
✓ Correct: C. Pass, Drop, or Forward to stateful

Q25.A stateful rule group uses the classic action order. Which rule wins for a flow that matches both a Pass rule and a Drop rule?

CThe Drop rule, because a deny always overrides an allow
DWhichever of the two rules has the lower SID number
✓ Correct: B. The Pass rule, since Pass is evaluated before Drop
