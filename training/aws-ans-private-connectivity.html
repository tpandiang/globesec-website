VPC PeeringFundamental
Q1.What does a VPC peering connection do?
APrivately links two VPCs so they route via private IPs
BConnects many VPCs through one central regional router
CBuilds an encrypted IPsec tunnel between a VPC and a data center
DExposes one service from a VPC to consumers through an NLB
✓ Correct: A. Privately links two VPCs so they route via private IPs

How to think about it: Peering = a private 1:1 link between two VPCs over the AWS network, so they route to each other like one network.

Why A is correct: Peering joins exactly two VPCs over the AWS backbone; traffic uses private addresses and never touches the internet.

Why the others are wrong:
B) Connects many VPCs through one central regional router — That is a Transit Gateway; peering is strictly a point-to-point link between two VPCs.
C) Builds an encrypted IPsec tunnel between a VPC and a data center — That is Site-to-Site VPN; peering connects VPC to VPC, not VPC to on-premises.
D) Exposes one service from a VPC to consumers through an NLB — That is PrivateLink with an endpoint service, which shares a single service rather than whole networks.
VPC PeeringFundamental
Q2.VPC-A is peered with VPC-B, and VPC-B is peered with VPC-C. Can instances in VPC-A reach VPC-C through VPC-B?
AYes, if all three VPCs are in the same AWS account and Region
BYes, but only for TCP 443 traffic through VPC-B
CYes, if VPC-B's route table has routes to both A and C
DNo; peering is not transitive, so A and C need a direct peering
✓ Correct: D. No; peering is not transitive, so A and C need a direct peering

How to think about it: Peering is non-transitive: every pair that must talk needs its own peering (or use a Transit Gateway).

Why D is correct: AWS drops traffic that tries to transit a peered VPC, so a direct A-to-C peering is required.

Why the others are wrong:
A) Yes, if all three VPCs are in the same AWS account and Region — Account ownership does not matter; the non-transitive rule applies to every peering.
B) Yes, but only for TCP 443 traffic through VPC-B — There is no protocol exception; transitive peering is unsupported for all traffic.
C) Yes, if VPC-B's route table has routes to both A and C — Route entries in the middle VPC do not help; transit routing through a peered VPC is never allowed.
VPC PeeringFundamental
Q3.Which condition prevents two VPCs from being peered?
AOne VPC also has an internet gateway attached
BTheir IPv4 CIDR blocks overlap
CThey belong to different AWS accounts
DThey are in different AWS Regions
✓ Correct: B. Their IPv4 CIDR blocks overlap

How to think about it: Peering needs non-overlapping CIDRs; overlapping ranges cannot be routed.

Why B is correct: Routes to the peer would clash with the local route, so AWS refuses to create the peering.

Why the others are wrong:
A) One VPC also has an internet gateway attached — An internet gateway does not block peering; it just cannot be used by the peer.
C) They belong to different AWS accounts — Cross-account peering is supported; the other account just has to accept the request.
D) They are in different AWS Regions — Inter-Region peering is supported and encrypted over the AWS backbone.
VPC PeeringFundamental
Q4.After a peering connection is accepted, instances still cannot reach each other. What is the most common missing step?
AEnabling Enhanced Networking (ENA) on the instances
BCreating a NAT gateway in each VPC for the peer traffic
CAttaching a virtual private gateway to both VPCs for routing
DRoutes to the peer's CIDR via the pcx- connection on both sides
✓ Correct: D. Routes to the peer's CIDR via the pcx- connection on both sides

How to think about it: Peering is only plumbing: you must add routes in both VPCs' route tables (and allow it in SGs/NACLs).

Why D is correct: AWS does not add peering routes automatically; each side needs a route to the other CIDR via the peering connection.

Why the others are wrong:
A) Enabling Enhanced Networking (ENA) on the instances — Enhanced Networking improves performance; it does not create reachability.
B) Creating a NAT gateway in each VPC for the peer traffic — NAT gateways are for outbound internet or private NAT, not for reaching a peered VPC.
C) Attaching a virtual private gateway to both VPCs for routing — A VGW is for VPN or Direct Connect and is not involved in peering.
VPC PeeringFundamental
Q5.How many peering connections can exist between the same two VPCs?
AExactly one
BUnlimited, as long as each uses a different route table
CTwo, one for each direction
DUp to four, for higher bandwidth
✓ Correct: A. Exactly one

How to think about it: Two VPCs = one peering connection, never more.

Why A is correct: AWS allows a single active peering connection between any pair of VPCs.

Why the others are wrong:
B) Unlimited, as long as each uses a different route table — Route tables do not change the one-per-pair limit.
C) Two, one for each direction — A single peering connection already carries traffic in both directions.
D) Up to four, for higher bandwidth — Peering has no aggregation model; there is no bandwidth reason or option for multiples.
VPC PeeringAdvanced
Q6.VPC-A has a NAT gateway and an internet gateway. A peered VPC-B wants to send its internet traffic out through VPC-A's NAT gateway to save cost. What happens?
AIt works only if both VPCs are in the same AWS account
BIt works if the NAT gateway is swapped for a NAT instance
CIt works once VPC-B adds a 0.0.0.0/0 route to the peering connection
DIt fails; a peer cannot use another VPC's NAT gateway or IGW
✓ Correct: D. It fails; a peer cannot use another VPC's NAT gateway or IGW

How to think about it: No edge-to-edge routing over peering: a peer cannot use your IGW, NAT gateway, VPN or Direct Connect.

Why D is correct: Traffic from VPC-B that is not destined for VPC-A's own addresses is dropped; use a Transit Gateway with a central egress VPC instead.

Why the others are wrong:
A) It works only if both VPCs are in the same AWS account — Ownership does not change the rule; edge-to-edge routing over peering is never allowed.
B) It works if the NAT gateway is swapped for a NAT instance — A NAT instance has the same problem: peering drops traffic whose destination is not inside the peer VPC.
C) It works once VPC-B adds a 0.0.0.0/0 route to the peering connection — The route can be created, but AWS drops the traffic because edge-to-edge routing is unsupported.
VPC PeeringAdvanced
Q7.A company has 300 VPCs that all need to reach each other, and teams keep adding more. Why is a full mesh of VPC peering a poor fit?
APeering adds more latency per hop than a Transit Gateway does
BPeering cannot be used between VPCs owned by different accounts
CPeering charges a fixed hourly fee for each connection created
DThe mesh needs ~45,000 links and exceeds the per-VPC peering limit
✓ Correct: D. The mesh needs ~45,000 links and exceeds the per-VPC peering limit

How to think about it: Mesh peering grows as n(n-1)/2 links and hits the per-VPC peering quota; many VPCs = Transit Gateway.

Why D is correct: 300 VPCs need 300*299/2 = 44,850 peerings, and each VPC can only hold up to 125, so a hub such as Transit Gateway is needed.

Why the others are wrong:
A) Peering adds more latency per hop than a Transit Gateway does — Peering actually has no extra hop; latency is not the reason to avoid it.
B) Peering cannot be used between VPCs owned by different accounts — Cross-account peering works; the problem is scale, not accounts.
C) Peering charges a fixed hourly fee for each connection created — Peering has no hourly fee; the issue is the number of links and route management.
Gateway EndpointsFundamental
Q8.Which AWS services can be reached through a VPC gateway endpoint?
AAny AWS service in the same Region
BAmazon EC2 and AWS Systems Manager
CAmazon S3 and Amazon DynamoDB
DAmazon S3, SQS and SNS
✓ Correct: C. Amazon S3 and Amazon DynamoDB

How to think about it: Gateway endpoint = S3 and DynamoDB only.

Why C is correct: These are the only two services that offer gateway endpoints.

Why the others are wrong:
A) Any AWS service in the same Region — Most services use interface endpoints; only S3 and DynamoDB have gateway endpoints.
B) Amazon EC2 and AWS Systems Manager — These APIs use interface endpoints powered by PrivateLink.
D) Amazon S3, SQS and SNS — SQS and SNS are reached through interface endpoints, not gateway endpoints.
Gateway EndpointsFundamental
Q9.How does traffic get directed to a gateway endpoint?
AA route to the service prefix list in chosen route tables
BDNS is changed so the service name resolves to a private IP
CAn ENI with a private IP is created in each chosen subnet
DA security group is attached to the endpoint to allow traffic
✓ Correct: A. A route to the service prefix list in chosen route tables

How to think about it: Gateway endpoint = a route table target using the service's prefix list (pl-xxxx).

Why A is correct: Gateway endpoints work at the routing layer; only subnets whose route tables have the entry use the endpoint.

Why the others are wrong:
B) DNS is changed so the service name resolves to a private IP — Gateway endpoints keep public service IPs; routing, not DNS, sends traffic to the endpoint.
C) An ENI with a private IP is created in each chosen subnet — That is how interface endpoints work; gateway endpoints create no ENI.
D) A security group is attached to the endpoint to allow traffic — Gateway endpoints do not take security groups; you control access with endpoint and resource policies.
Gateway EndpointsFundamental
Q10.What does a gateway endpoint cost?
AAn hourly charge per AZ plus a per-GB processing fee
BNothing; no hourly or data processing charge
CA per-GB fee equal to NAT gateway data processing
DA monthly fee per route table it is associated with
✓ Correct: B. Nothing; no hourly or data processing charge

How to think about it: Gateway endpoints are free; interface endpoints charge per hour and per GB.

Why B is correct: That is why gateway endpoints are the default choice for S3/DynamoDB traffic from inside the VPC.

Why the others are wrong:
A) An hourly charge per AZ plus a per-GB processing fee — That is the pricing model for interface endpoints.
C) A per-GB fee equal to NAT gateway data processing — Using a gateway endpoint avoids NAT processing fees instead of adding them.
D) A monthly fee per route table it is associated with — There is no per-route-table charge for gateway endpoints.
Gateway EndpointsAdvanced
Q11.On-premises servers connected over Direct Connect must upload to S3 privately. A gateway endpoint for S3 already exists in the VPC, but the on-premises traffic cannot use it. What should be added?
AA second S3 gateway endpoint in another subnet of the VPC
BA route on the on-premises router to the gateway endpoint prefix list
CAn S3 interface endpoint, reachable over DX by private IP
DA NAT gateway in the VPC to forward the on-premises traffic
✓ Correct: C. An S3 interface endpoint, reachable over DX by private IP

How to think about it: Gateway endpoints only serve traffic from inside their own VPC. From on-prem, peered VPCs or TGW, use an S3 interface endpoint.

Why C is correct: Interface endpoints are ENIs with VPC addresses, so on-premises hosts can reach them through DX or VPN.

Why the others are wrong:
A) A second S3 gateway endpoint in another subnet of the VPC — More gateway endpoints do not change the rule that only in-VPC traffic can use them.
B) A route on the on-premises router to the gateway endpoint prefix list — Gateway endpoints cannot be reached from outside the VPC, whatever routes are added on-premises.
D) A NAT gateway in the VPC to forward the on-premises traffic — A NAT gateway sends traffic to S3 public endpoints and cannot serve on-premises traffic through the VPC this way.
Gateway EndpointsAdvanced
Q12.Private-subnet instances access S3 through a NAT gateway, and NAT data-processing charges are high. What is the simplest way to cut this cost?
APoint the private subnets at an internet gateway instead
BCreate an S3 interface endpoint in every Availability Zone
CAdd an S3 gateway endpoint to the private route tables
DEnable S3 Transfer Acceleration on the destination bucket
✓ Correct: C. Add an S3 gateway endpoint to the private route tables

How to think about it: S3 traffic through NAT = wasted money; add a free S3 gateway endpoint to the private route tables.

Why C is correct: The prefix-list route is more specific than 0.0.0.0/0, so S3 traffic bypasses the NAT gateway at no charge.

Why the others are wrong:
A) Point the private subnets at an internet gateway instead — That would turn the subnets public and expose the instances.
B) Create an S3 interface endpoint in every Availability Zone — It works, but interface endpoints charge hourly and per GB, so it is not the cheapest option.
D) Enable S3 Transfer Acceleration on the destination bucket — Transfer Acceleration speeds up long-distance uploads through edge locations; it does not avoid NAT charges.
Interface EndpointsFundamental
Q13.What does an interface VPC endpoint create inside your VPC?
AA new subnet dedicated to AWS service traffic
BAn ENI with a private IP in each selected subnet
CA route table entry that uses a managed prefix list
DAn internet gateway limited to AWS service IP ranges
✓ Correct: B. An ENI with a private IP in each selected subnet

How to think about it: Interface endpoint = an ENI with a private IP in each chosen subnet, powered by PrivateLink.

Why B is correct: Clients reach the service by connecting to these ENIs, so traffic stays on the AWS network.

Why the others are wrong:
A) A new subnet dedicated to AWS service traffic — The endpoint uses subnets you choose; it does not create subnets.
C) A route table entry that uses a managed prefix list — That describes a gateway endpoint, not an interface endpoint.
D) An internet gateway limited to AWS service IP ranges — Interface endpoints remove the need for internet gateways; they do not create one.
Interface EndpointsFundamental
Q14.Which control can be attached directly to an interface endpoint's network interfaces to limit which clients connect to it?
AAn AWS WAF web ACL
BA security group
CA Route 53 Resolver firewall rule group
DA route table
✓ Correct: B. A security group

How to think about it: Interface endpoints are ENIs, so they take a security group (e.g. inbound 443 from the VPC CIDR).

Why B is correct: The endpoint's security group decides which sources can open connections to the endpoint ENIs.

Why the others are wrong:
A) An AWS WAF web ACL — WAF attaches to CloudFront, ALB, API Gateway and similar, not to VPC endpoints.
C) A Route 53 Resolver firewall rule group — DNS Firewall filters DNS queries; it does not control connections to the endpoint ENI.
D) A route table — Route tables control gateway endpoints; interface endpoints are reached by IP within the VPC's local route.
Interface EndpointsFundamental
Q15.For high availability of an interface endpoint, what should you do?
ACreate two endpoints for the same service in one subnet
BPut an Application Load Balancer in front of the endpoint
CSelect a subnet in each of several Availability Zones
DCreate the endpoint in a single subnet and enable cross-zone load balancing
✓ Correct: C. Select a subnet in each of several Availability Zones

How to think about it: One endpoint ENI per AZ; pick subnets in multiple AZs.

Why C is correct: Each AZ gets its own endpoint ENI, so the endpoint keeps working if one AZ fails.

Why the others are wrong:
A) Create two endpoints for the same service in one subnet — Both would sit in the same AZ, so an AZ outage would still break access.
B) Put an Application Load Balancer in front of the endpoint — This adds cost and complexity; multi-AZ endpoint subnets already give HA.
D) Create the endpoint in a single subnet and enable cross-zone load balancing — Cross-zone is an NLB setting; a single-AZ endpoint is still a single point of failure.
Interface EndpointsFundamental
Q16.Which networks can reach an interface endpoint in a VPC?
AOnly resources that have a public IP address assigned
BOnly resources inside the same VPC as the endpoint
COnly resources in the same AZ as the endpoint ENI
DThe VPC, peered and TGW VPCs, and on-premises over VPN or DX
✓ Correct: D. The VPC, peered and TGW VPCs, and on-premises over VPN or DX

How to think about it: Interface endpoints have real VPC IPs, so they are reachable over peering, Transit Gateway, VPN and Direct Connect.

Why D is correct: Any network that can route to the endpoint ENIs' private IPs can use it, which is why central endpoints are possible.

Why the others are wrong:
A) Only resources that have a public IP address assigned — Endpoints serve private clients; public IPs are not required.
B) Only resources inside the same VPC as the endpoint — That restriction applies to gateway endpoints, not interface endpoints.
C) Only resources in the same AZ as the endpoint ENI — Any AZ in the VPC can use the endpoint, though same-AZ use avoids cross-AZ charges.
Interface EndpointsAdvanced
Q17.A company has 80 VPCs, each with its own SQS, KMS and STS interface endpoints in two AZs. Endpoint costs are high. What design reduces the cost?
ASwap the interface endpoints for SQS, KMS and STS gateway endpoints
BCreate them once in a central VPC on the TGW, with shared PHZs
CDelete the endpoints and use a NAT gateway in each VPC
DKeep one endpoint per VPC but put each in a single AZ
✓ Correct: B. Create them once in a central VPC on the TGW, with shared PHZs

How to think about it: Many VPCs x many endpoints = $$$. Centralize interface endpoints in a shared-services VPC reached through Transit Gateway, and fix DNS with PHZs.

Why B is correct: Spoke VPCs reach the central ENIs through TGW; with private DNS turned off, PHZs (alias to the endpoint) associated with the spokes make the service names resolve to the central endpoints.

Why the others are wrong:
A) Swap the interface endpoints for SQS, KMS and STS gateway endpoints — Gateway endpoints exist only for S3 and DynamoDB.
C) Delete the endpoints and use a NAT gateway in each VPC — This puts traffic back on public endpoints and NAT processing charges, which is not the goal.
D) Keep one endpoint per VPC but put each in a single AZ — This saves a little but loses high availability and still pays for 80 copies.
Interface EndpointsAdvanced
Q18.An interface endpoint for an AWS service and its consumer instances are in different AZs, and inter-AZ data charges are rising. What can the client application do?
ATurn on cross-zone load balancing on the endpoint
BUse the endpoint's regional DNS name instead
CMove the endpoint ENIs to a public subnet
DUse the endpoint's zonal DNS name for its own AZ
✓ Correct: D. Use the endpoint's zonal DNS name for its own AZ

How to think about it: Regional DNS = round-robin across all AZ ENIs; zonal DNS name = stays in your own AZ.

Why D is correct: Each endpoint has AZ-specific DNS names; using the local one avoids cross-AZ data transfer.

Why the others are wrong:
A) Turn on cross-zone load balancing on the endpoint — Interface endpoints have no cross-zone setting; that applies to the provider's NLB.
B) Use the endpoint's regional DNS name instead — The regional name can return an ENI in any AZ, which is what causes cross-AZ traffic.
C) Move the endpoint ENIs to a public subnet — Subnet type does not affect which AZ the traffic crosses.
Endpoint DNSFundamental
Q19.With Private DNS enabled on an interface endpoint for SQS, what does sqs.us-east-1.amazonaws.com resolve to inside the VPC?
AThe endpoint ENIs' private IP addresses
BA link-local address in 169.254.0.0/16
CA CNAME to a CloudFront distribution
DThe public IP addresses of the SQS service
✓ Correct: A. The endpoint ENIs' private IP addresses

How to think about it: Private DNS ON = public service name resolves to the endpoint's private IPs, so SDKs need no code change.

Why A is correct: AWS adds a managed private hosted zone to the VPC, overriding the public name with the endpoint IPs.

Why the others are wrong:
B) A link-local address in 169.254.0.0/16 — Link-local addresses are used by VPC Lattice and the instance metadata service, not interface endpoints.
C) A CNAME to a CloudFront distribution — CloudFront is not involved in VPC endpoint DNS.
D) The public IP addresses of the SQS service — That is what happens with Private DNS turned off.
Endpoint DNSFundamental
Q20.Which two VPC attributes must be enabled for an interface endpoint's Private DNS to work?
AenableDnsSupport and enableDnsHostnames
BAuto-assign public IPv4 and enableDnsHostnames
CDNSSEC validation and DNS query logging
DenableNetworkAddressUsageMetrics and enableDnsSupport
✓ Correct: A. enableDnsSupport and enableDnsHostnames

How to think about it: Private DNS needs enableDnsSupport and enableDnsHostnames both set to true.

Why A is correct: The Amazon-provided resolver must be on, and DNS hostnames must be enabled, for the managed private zone to answer.

Why the others are wrong:
B) Auto-assign public IPv4 and enableDnsHostnames — Public IP assignment has nothing to do with endpoint DNS.
C) DNSSEC validation and DNS query logging — These are optional Resolver features and are not prerequisites for Private DNS.
D) enableNetworkAddressUsageMetrics and enableDnsSupport — Network Address Usage metrics are about IP quota tracking, not DNS.
Endpoint DNSFundamental
Q21.Without Private DNS enabled, how must an application reach an interface endpoint?
AUse the normal service name; it resolves privately anyway
BUse the instance metadata service to discover the endpoint
CUse the endpoint-specific vpce- DNS name (e.g. --endpoint-url)
DUse the SQS service's public IP address directly in code
✓ Correct: C. Use the endpoint-specific vpce- DNS name (e.g. --endpoint-url)

How to think about it: Private DNS OFF = use the endpoint-specific DNS name (vpce-xxxx...vpce.amazonaws.com), e.g. with --endpoint-url.

Why C is correct: The default service name still resolves to public IPs, so the client must point at the vpce- name explicitly.

Why the others are wrong:
A) Use the normal service name; it resolves privately anyway — Only Private DNS (or your own PHZ) makes the normal name resolve to the endpoint.
B) Use the instance metadata service to discover the endpoint — IMDS does not publish endpoint addresses.
D) Use the SQS service's public IP address directly in code — That goes over the internet path, not through the endpoint.
Endpoint DNSAdvanced
Q22.In a hub-and-spoke design with central interface endpoints, the spoke VPCs keep resolving kms.us-east-1.amazonaws.com to public IPs. What fixes this?
AEnable Private DNS on the central endpoint a second time for each spoke
BAdd a route to the KMS public IPs via the Transit Gateway in each spoke
CTurn on enableDnsHostnames and enableDnsSupport in each spoke
DDisable Private DNS, then associate a KMS-name PHZ with the spokes
✓ Correct: D. Disable Private DNS, then associate a KMS-name PHZ with the spokes

How to think about it: The endpoint's managed private zone only applies to its own VPC. For spokes: disable Private DNS, create a PHZ for the service name with an alias to the endpoint, associate it with the spokes.

Why D is correct: The spokes then resolve the service name to the central endpoint IPs and reach them through Transit Gateway.

Why the others are wrong:
A) Enable Private DNS on the central endpoint a second time for each spoke — Private DNS only works in the endpoint's own VPC; it cannot be applied to other VPCs.
B) Add a route to the KMS public IPs via the Transit Gateway in each spoke — Routing public IPs toward TGW does not reach the private endpoint and is not a supported pattern.
C) Turn on enableDnsHostnames and enableDnsSupport in each spoke — These attributes alone do not give spokes any record pointing to the central endpoint.
Endpoint DNSAdvanced
Q23.On-premises servers must resolve the AWS service names of central interface endpoints over Direct Connect. What should be added to the DNS design?
ADHCP options sets pointing on-premises hosts at 169.254.169.253
BA Route 53 Resolver outbound endpoint in the hub VPC only
CA public hosted zone holding the endpoint private IPs
DA Resolver inbound endpoint in the hub, with on-prem forwarding
✓ Correct: D. A Resolver inbound endpoint in the hub, with on-prem forwarding

How to think about it: On-prem DNS into AWS private zones = Route 53 Resolver inbound endpoint plus a conditional forwarder on-prem.

Why D is correct: The inbound endpoint lets on-premises resolvers query the VPC's DNS view, including PHZs that point at the endpoints.

Why the others are wrong:
A) DHCP options sets pointing on-premises hosts at 169.254.169.253 — That resolver address is only reachable from inside the VPC.
B) A Route 53 Resolver outbound endpoint in the hub VPC only — Outbound endpoints send queries from AWS to on-premises; this flow is the other way.
C) A public hosted zone holding the endpoint private IPs — Publishing private IPs in public DNS is poor practice, and the service domain is not yours to host.
Endpoint PoliciesFundamental
Q24.What is a VPC endpoint policy?
AA security group that filters ports on the endpoint ENIs
BAn IAM permission boundary for every role in the VPC
CA resource policy on the endpoint that limits who can use it
DA route table rule deciding which subnets use the endpoint
✓ Correct: C. A resource policy on the endpoint that limits who can use it

How to think about it: Endpoint policy = a resource-based IAM policy on the endpoint that limits what can be done through it.

Why C is correct: It is evaluated with identity and resource policies, and can only narrow access, never grant extra.

Why the others are wrong:
A) A security group that filters ports on the endpoint ENIs — Security groups are network controls on interface ENIs, separate from endpoint policies.
B) An IAM permission boundary for every role in the VPC — Permission boundaries apply to IAM principals, not to VPC endpoints.
D) A route table rule deciding which subnets use the endpoint — Route association affects gateway endpoints, but it is not the endpoint policy.
Endpoint PoliciesFundamental
Q25.If no endpoint policy is specified when you create a VPC endpoint, what access does it allow?
ARead-only access to the service's Describe/Get APIs
BNo access at all until a custom policy is attached
CFull access, subject to IAM and resource policies
DAccess only for the account that created the endpoint
✓ Correct: C. Full access, subject to IAM and resource policies

How to think about it: No policy = default full access; other IAM and resource policies still apply.

Why C is correct: The default policy allows all principals and actions; your identity and bucket policies still decide what succeeds.

Why the others are wrong:
A) Read-only access to the service's Describe/Get APIs — There is no read-only default; the default is full access.
B) No access at all until a custom policy is attached — Endpoints work right away with the default allow-all policy.
D) Access only for the account that created the endpoint — The default does not restrict by account; you would need a custom policy for that.
Endpoint PoliciesAdvanced
Q26.A bucket must only be reachable through a specific S3 VPC endpoint. Which bucket policy condition key does this?
Aaws:SourceVpce in a Deny for other paths
Baws:PrincipalOrgID with the organization ID
Cs3:x-amz-acl set to bucket-owner-full-control
Daws:SourceIp with the VPC's private CIDR range
✓ Correct: A. aws:SourceVpce in a Deny for other paths

How to think about it: Lock a bucket to an endpoint = aws:SourceVpce; lock to a whole VPC = aws:SourceVpc.

Why A is correct: This rejects any request that does not arrive through the named endpoint ID.

Why the others are wrong:
B) aws:PrincipalOrgID with the organization ID — This limits callers to your Organization, not to a particular endpoint path.
C) s3:x-amz-acl set to bucket-owner-full-control — This is about object ACLs, not where the request came from.
D) aws:SourceIp with the VPC's private CIDR range — aws:SourceIp checks public source IPs; requests through an endpoint carry private addresses, so use aws:VpcSourceIp or the endpoint keys.
Endpoint PoliciesAdvanced
Q27.An administrator adds a bucket policy that denies all access unless it comes from the production VPC endpoint. Soon after, console users and a CI pipeline outside the VPC lose access. Why?
AThe CI pipeline needs its own gateway endpoint in its Region
BBucket policies cannot be combined with VPC endpoints
CEndpoint policies always block AWS console access
DThe explicit Deny blocks every path except that endpoint
✓ Correct: D. The explicit Deny blocks every path except that endpoint

How to think about it: A Deny unless aws:SourceVpce blocks everyone else too, including admins in the console; add the exceptions on purpose.

Why D is correct: An explicit deny overrides allows, so any path outside the endpoint is blocked unless you add exceptions.

Why the others are wrong:
A) The CI pipeline needs its own gateway endpoint in its Region — The issue is the Deny condition, not the pipeline's network path.
B) Bucket policies cannot be combined with VPC endpoints — They are commonly combined; this policy is simply too strict.
C) Endpoint policies always block AWS console access — Endpoint policies only affect traffic through the endpoint; this outage is caused by the bucket policy.
Endpoint ServicesFundamental
Q28.A company wants to offer its own application privately to customers' VPCs using PrivateLink. What must sit in front of the application in the provider VPC?
AA Network Load Balancer
BAn Application Load Balancer only
CA Transit Gateway attachment
DAn internet gateway and an Elastic IP
✓ Correct: A. A Network Load Balancer

How to think about it: PrivateLink endpoint service = NLB (or GWLB for appliances) in the provider VPC + interface endpoint in each consumer VPC.

Why A is correct: An endpoint service is built on an NLB that fronts the application targets.

Why the others are wrong:
B) An Application Load Balancer only — An ALB can be an NLB target, but the endpoint service itself must be backed by an NLB or GWLB.
C) A Transit Gateway attachment — TGW connects networks; PrivateLink shares a service without network-level connectivity.
D) An internet gateway and an Elastic IP — PrivateLink avoids the internet; no IGW is needed.
Endpoint ServicesFundamental
Q29.With PrivateLink, which side can open new connections?
ABoth sides equally, like VPC peering does
BOnly the consumer; the provider only replies
COnly the provider, toward its consumers
DWhichever side created the connection first
✓ Correct: B. Only the consumer; the provider only replies

How to think about it: PrivateLink is one-way: the consumer starts the connection, and the provider can only reply.
