Q1.A team wants to orchestrate several Lambda functions as a visual workflow with branches, retries and timeouts, without writing glue code. Which service fits?
AAmazon SQS
BAmazon SNS
CAmazon EventBridge Scheduler
DAWS Step Functions
✓ Correct: D. AWS Step Functions

How to think about it: Serverless orchestration as a JSON state machine = Step Functions.

Why D is correct: Step Functions models the workflow as a state machine in Amazon States Language, with built-in branching, retries and timeouts.

Why the others are wrong:
A) Amazon SQS — A queue decouples two parts but does not model a multi-step workflow.
B) Amazon SNS — SNS pushes messages to subscribers; it keeps no workflow state.
C) Amazon EventBridge Scheduler — Scheduler starts targets on a schedule but does not orchestrate the steps.

Q22.After a consumer receives an SQS message, what keeps other consumers from receiving it while it is being processed?

BThe message retention period
CThe receive wait time
DThe visibility timeout
✓ Correct: D. The visibility timeout

How to think about it: Hidden while in progress = visibility timeout; delete when done or it reappears.

Q28.When does SQS move a message to a dead-letter queue?
AAfter more receives than maxReceiveCount allows
BWhen the message is older than one hour
CAs soon as the consumer throws an exception
DWhen the visibility timeout is set to zero
✓ Correct: A. After more receives than maxReceiveCount allows

How to think about it: DLQ = message received more than maxReceiveCount times (redrive policy).

Why A is correct: Each failed attempt returns the message to the queue, and past the threshold it moves to the DLQ.

Why the others are wrong:
B) When the message is older than one hour — Age alone does not move messages; expiry deletes them.
C) As soon as the consumer throws an exception — SQS does not see consumer errors; it only counts receives.
D) When the visibility timeout is set to zero — This changes timing but does not trigger the DLQ.
