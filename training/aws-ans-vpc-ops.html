VPC DNSFundamental
Q1.Where does the Amazon-provided DNS server (Route 53 Resolver) listen inside a VPC?
AVPC base +2, and 169.254.169.253
BThe last address of each subnet
C8.8.8.8, the public Google resolver
D169.254.169.254, the metadata IP
✓ Correct: A. VPC base +2, and 169.254.169.253

How to think about it: VPC DNS = VPC base + 2 (e.g. 10.0.0.2) or 169.254.169.253.

Why A is correct: Both addresses reach the same Route 53 Resolver from inside the VPC.

Why the others are wrong:
B) The last address of each subnet — The last address is reserved and not used for DNS.
C) 8.8.8.8, the public Google resolver — That is a public Google resolver, not the AWS VPC resolver.
D) 169.254.169.254, the metadata IP — That is the instance metadata service, not DNS.

Q2.What can the Amazon-provided DNS resolver answer for instances in a VPC?
AOnly on-premises corporate domain names
BOnly names registered in the account's default VPC itself
CPrivate zones, EC2 internal names and public DNS
DOnly public internet domain names, never private
✓ Correct: C. Private zones, EC2 internal names and public DNS

How to think about it: .2 resolver = private hosted zones + VPC internal names + public DNS.

Why C is correct: The resolver handles private hosted zones associated with the VPC, internal hostnames and internet names by default.

Why the others are wrong:
A) Only on-premises corporate domain names — On-premises names need an outbound Resolver endpoint with forwarding rules.
B) Only names registered in the account's default VPC itself — Every VPC has its own resolver.
D) Only public internet domain names, never private — It also answers private hosted zones and internal EC2 names.

Q3.What does the VPC attribute enableDnsSupport control?
AWhether the Amazon DNS resolver works
BWhether instances get public DNS names
CWhether DHCP is enabled in the VPC
DWhether DNSSEC answers are validated
✓ Correct: A. Whether the Amazon DNS resolver works

How to think about it: enableDnsSupport = is the .2 resolver on. enableDnsHostnames = do instances get public DNS names.

Why A is correct: If it is false, instances cannot use the .2 resolver.

Why the others are wrong:
B) Whether instances get public DNS names — That is enableDnsHostnames.
C) Whether DHCP is enabled in the VPC — DHCP is always on in a VPC.
D) Whether DNSSEC answers are validated — DNSSEC validation is a separate Resolver setting.

MTU & JumboAdvanced
Q19.Large packets from a VPC to an on-premises host keep getting dropped, while small packets work. Path MTU Discovery seems broken. What rule should you add?
AAllow inbound ICMP type 3, code 4
BDisable the source/destination check
CAllow inbound TCP and UDP port 53
DMove the subnet to IPv6-only addressing
✓ Correct: A. Allow inbound ICMP type 3, code 4

How to think about it: PMTUD needs ICMP type 3 code 4 ("fragmentation needed") allowed in.

Why A is correct: This is Destination Unreachable: Fragmentation Needed; without it the sender never learns to send smaller packets.

Why the others are wrong:
B) Disable the source/destination check — That is for NAT and routing instances, not PMTUD.
C) Allow inbound TCP and UDP port 53 — Port 53 is DNS and does not affect packet size.
D) Move the subnet to IPv6-only addressing — IPv6 also needs ICMPv6 Packet Too Big messages, so the core problem stays.

Q20.A data transfer between EC2 instances in the same VPC is limited by packets per second, not bandwidth. What tuning helps?

BLower the instance MTU down to 1500
CUse jumbo frames with an MTU of 9001
DRoute the flow through an internet gateway
✓ Correct: C. Use jumbo frames with an MTU of 9001

How to think about it: PPS bottleneck = bigger packets (jumbo frames, MTU 9001).

Why C is correct: Fewer, larger packets move more data at the same packet rate.

Why the others are wrong:
A) Turn off enhanced networking on both — Enhanced networking raises PPS; turning it off hurts.
B) Lower the instance MTU down to 1500 — Smaller packets need more packets per second, making it worse.
D) Route the flow through an internet gateway — This adds a 1500 MTU limit and a longer path.

Q40.Compliance wants proof that no path exists from the internet to the database subnets except through the inspection firewall. Which tool fits?
