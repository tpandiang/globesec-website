Q1.An S3 bucket was deleted overnight and nobody admits doing it. Where should you look first to find who made the call?
AAmazon CloudWatch metrics
BVPC Flow Logs
CAmazon Inspector findings
DAWS CloudTrail event history
✓ Correct: D. AWS CloudTrail event history

How to think about it: Who did what, when, through which API = CloudTrail.

Why D is correct: CloudTrail records API calls from the console, CLI, SDKs and services, including the caller identity, so it shows who ran DeleteBucket.

Why the others are wrong:
A) Amazon CloudWatch metrics — Metrics are numeric time series; they do not record which principal issued an API call.
B) VPC Flow Logs — Flow Logs capture IP traffic metadata for network interfaces, not AWS API calls or identities.
C) Amazon Inspector findings — Inspector scans workloads for vulnerabilities and does not keep an audit trail of API activity.

✓ Correct: C. EventBridge rule on the CloudTrail DeleteTable event, targeting Lambda

Q10.Which statement about a KMS key created in us-east-1 is true?
AIt can be exported in plaintext for use in another Region
BIt is automatically available in every Region of the account
CIt can be used only in us-east-1 unless it is a multi-Region key
DIt can be used in any Region where the account has a VPC
✓ Correct: C. It can be used only in us-east-1 unless it is a multi-Region key

How to think about it: KMS keys are regional; use multi-Region keys to share key material.

Why C is correct: Standard KMS keys are bound to their Region; only multi-Region keys have related replicas elsewhere.

Why the others are wrong:
A) It can be exported in plaintext for use in another Region — KMS never exposes symmetric key material in plaintext.
B) It is automatically available in every Region of the account — Ordinary KMS keys do not replicate; each Region has its own keys.
D) It can be used in any Region where the account has a VPC — Having a VPC in a Region does not extend a regional key to it.

Q26.In a TLS handshake, why is asymmetric encryption used only at the start?

BSymmetric encryption is required by DNSSEC
CThe server's private key is sent to the client after the handshake
DIt is costly, so it only protects the exchange of a symmetric session key
